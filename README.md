# grafia concisă

Rules: [`concise-writing-spec.md`](concise-writing-spec.md) (in Romanian: [`README.ro.md`](README.ro.md)); settled decisions and their reasons: [`DECISIONS.md`](DECISIONS.md).

The project uses [uv](https://docs.astral.sh/uv/) only, never pip: `uv sync` sets up the environment from `uv.lock`, and every command runs with `uv run`.

```
uv run python pipeline/seed_db.py                    # small dev DB (no MySQL), or the full one, see below
uv run python -m unittest discover -s server         # tests
uv run flask --app server/server.py run              # dev server
docker build -t grafia-concisa . && docker run -p 10000:10000 grafia-concisa
```

## Building the full database from dexonline

`word_db.sqlite` is built from [dexonline](https://dexonline.ro)'s public database dump. The data is GPL, and the attribution must stay in the UI.

The steps are:
1. A local MariaDB (or MySQL) server.
2. Load the dump's three tables into it (`pipeline/load_dexonline.py`).
3. Build `word_db.sqlite` from them (`pipeline/build_db.py`).

All of it is repeatable. Steps 2 and 3 are also how dexonline updates come in.

### 1. A MariaDB server (once)

Any MariaDB or MySQL works. On Windows, the portable zip needs no installer and no service:

```bash
# from https://mariadb.org/download/ : the "ZIP file" package, e.g. mariadb-11.4.13-winx64.zip
M=/path/to/mariadb-11.4.13-winx64/bin        # where the zip was unpacked
D=/path/to/mariadb-data                      # data directory (about 800 MB once loaded)
"$M/mariadb-install-db.exe" --datadir="$D" --port=3307   # once: creates the data dir and $D/my.ini
"$M/mariadbd.exe" --defaults-file="$D/my.ini" --console  # start (runs in the foreground)
"$M/mariadb-admin.exe" -uroot -P3307 -h127.0.0.1 shutdown  # stop
```

The server then listens on `127.0.0.1:3307`, as user `root` with no password. Port 3307 avoids clashing with any other MySQL.

On Linux or macOS, install MariaDB with the package manager instead; the default port is 3306.

### 2. Load dexonline

```bash
uv run python pipeline/load_dexonline.py --download --client "$M/mariadb.exe" --port 3307
```

- `--download` fetches `https://dexonline.ro/static/download/dex-database.sql.gz` into `data/` (about 380 MB, git- and docker-ignored). It also prints the dump's `Last-Modified` date; note that date, because it identifies the data the DB was built from.
- The dump is gzipped SQL from `mysqldump`, regenerated by dexonline about daily. Without `--download`, the script loads the dump already in `data/`.
- Only the tables `build_db.py` reads are imported: `Lexeme`, `InflectedForm`, `Inflection`, `EntryLexeme`, `EntryDefinition`, `Definition` and `Source`. They go into the database `dexonline` (utf8mb4, Romanian collation), and each run replaces them. The rest of the dump is skipped.
- A load takes about 3 minutes and ends by printing the row counts. For the 2026-10-04 dump: `Lexeme 320935`, `InflectedForm 2274627`.

### 3. Build `word_db.sqlite`

```bash
uv run --extra pipeline python pipeline/build_db.py --mysql --host 127.0.0.1 --port 3307 --database dexonline
```

This takes about a minute and prints its stats. As of 2026-10-07 (2026-10-04 dump): 292,072 forms stored, of which 102 homographs and 2,749 with an -ee spelling, plus 2,613 reverse -ee spellings (`ee_revert`, 129 of them ties), 1,066 lemmas in -eu (`eu_lemmas`), 3,434 in -ea (`ea_lemmas`) and 65 in -iesc (`iesc_lemmas`). Lemma syllabifications came from dexonline (4,165 complete, 6,601 partial), Cezar's explicit list (10) and the rules alone (80,918).

What the build reads:
- the inflected forms, with their lemma and number (`InflectedForm`, `Inflection`);
- each lemma's dexonline syllabification (`Lexeme.hyphenations`; complete or partial, completed by the rules);
- the frequent common words, which the prefix rule checks against (`Lexeme.frequency`);
- which lexemes are DEX-MDA-DOOM, with a definition of their own (`Definition.lexicon`) in a source named MDA\*, DEX\*, NODEX\* or DOOM\* (`EntryLexeme`, `EntryDefinition`, `Definition`, `Source`), for reverse -ee.

How these are turned into spellings is in the spec.

### Integrating a dexonline update

1. Start the server.
2. Run step 2 with `--download`, then step 3.
3. Run the tests.
4. Compare the build's stats with the previous ones (forms stored, homographs, lemma sources). A large jump points to a change in dexonline's data or schema worth looking at before deploying.

Updates are picked up automatically wherever dexonline's syllabifications changed or new words appeared. Cezar's explicit syllabifications (`rules.SYLLABIFICATIONS`) still prevail.

### Pitfalls

- **Stop the Flask dev server before building.** It keeps `word_db.sqlite` open, and on Windows the build's final replace then fails with "Access is denied". Alternatively, build elsewhere with `--out` and copy the file over.
- **Table names on Windows.** A Windows server stores table names in lowercase (`lexeme`). Queries are case-insensitive there, so nothing needs to change.
